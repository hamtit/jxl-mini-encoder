# アニメーション品質の評価記録

## 評価対象

GIF 由来の動画（420x236、134 フレーム、遅延 6〜7 cs）を PIL で全面合成して PNG 連番にし、
`examples/anim` で符号化して jxl-oxide で復号、SSIMULACRA2 で採点しました。
元素材は 256 色パレットのディザを含み、フレーム間はカメラ移動で大きく変わります。

## 原因

逆 Gaborish は、デコーダ側の Gaborish（平滑化）を打ち消すため、量子化前に画像を鮮鋭化します。
ノイズやディザの多い画像では、この鮮鋭化がノイズを増幅し、増えた成分を符号化するための
ビットが余計に必要になります。実写のきれいな静止画では逆に有利です
（同じ SSIMULACRA2 でのサイズ比、逆 Gaborish 無効 / 有効）。

| 画像 | 中央値ラプラシアン | 無効 / 有効 |
|---|---|---|
| tower（512x512 写真） | 2 | 1.01〜1.06（有効が有利） |
| large（1600x1067 写真） | 2 | 1.12（有効が有利） |
| GIF フレーム 3 枚（原寸） | 19〜28 | 0.94〜0.95（無効が有利） |
| GIF フレーム（半分に縮小） | 16〜27 | 0.94〜0.97（無効が有利） |

## 変更

`vardct::noise_level` が輝度の 4 近傍ラプラシアン絶対値の中央値（8 bit 単位、最大約 25 万画素を標本化）を求め、
`NOISY_LEVEL`（8）以上なら逆 Gaborish を使いません。アニメーションでは全フレームの中央値を
1 回だけ求め、全フレームで同じ設定を使います（しきい値付近でフレームごとに設定が切り替わるとちらつくため）。

## 結果（effort 7、`-q 75`、全 134 フレーム）

| | 変更前 | 変更後 |
|---|---|---|
| サイズ | 2,293,464 B | 2,198,021 B（−4.2%） |
| 平均 SSIMULACRA2 | 70.46 | 70.68 |
| 最小 SSIMULACRA2 | 68.74 | 68.96 |
| 同スコアのサイズ（サンプル 17 フレーム、65 / 70 / 75 / 80） | 244.0 / 289.9 / 346.8 / 430.9 KB | 229.9 / 274.6 / 329.2 / 411.5 KB（−4.7〜−5.8%） |
| `-q 90` のサイズ / 平均スコア | 4,192,824 B / 84.89 | 3,917,365 B / 84.32 |

同スコアでのサイズ比較（上から 3 行目）が公平な比較です。`-q 90` ではスコアがやや下がり、サイズも下がっています。
同じ品質値で比べるとスコアと容量の両方が動くため、必ず同スコアでのサイズで比べてください。

## 時間・メモリのトレードオフ

`--no-decode`、1 回の実行で 3 回測定した範囲。

| | 変更前 | 変更後 |
|---|---|---|
| 1 スレッド、時間 | 6.17〜6.39 s | 5.09〜5.40 s（約 −14%） |
| 4 スレッド、時間 | 3.76〜3.89 s | 3.48〜3.57 s（約 −8%） |
| ピーク RSS（1 / 4 スレッド） | 52〜53 / 61〜63 MB | 52〜53 / 61〜63 MB（変化なし） |

- ノイズ推定は画素を 1 回走査するだけで、メモリは固定サイズのヒストグラム（約 4 KB）です。
- ノイズが多い画像では逆 Gaborish を省くため、むしろ速くなります。
- ノイズが少ない画像（tower、large）は、出力がバイト単位で変更前と同じです。
- 時間・メモリが悪化する条件はありません。

## 未対応・今後の課題

- フレーム間予測は未実装です。各フレームを独立に符号化するため、カメラ移動のある素材ではサイズが大きくなります。
- ノイズ合成が未実装のため、ディザやノイズの質感は復号結果で滑らかになります（高周波成分が元の約 8〜18% 少ない）。
- しきい値 8 は、きれいな写真（2）とビデオ・GIF 由来（10 以上）の間に置いたもので、
  中間のノイズ量を持つ写真での検証は少数です。
